Baseline `2334c1068cf43f0de82fb271dc6c6a188108d5b9`, GameState 53, captured config 31. Paths in the tables are relative to GameState. `C` means `civilization`, `D` means `world.sites[].detailedState`, and `V` means the record selected by `C.vassalLineage.currentVassalId` in `C.vassalLineage.vassalsById`. ## Tick and second boundaries

1. `src/model/replay-second-runner.js:17` makes exactly 60 calls to `updateGame(1/60, state)` in the default official path. `src/model/game-model.js:24` calls `cmdTickSimulation` and performs no further gameplay. `src/model/commands/simulation-commands.js` rejects paused or complete runs without mutation.
2. Accepted tick increments `simStepIndex`; compare `floor(simStepIndex/60)` against old `tSec`. On a second boundary write `tSec`, normalize AP, recompute its cap, add income and clamp `actionPoints`. Cap uses `apCapOverride` or the AP table, time and global skill modifier. See `src/model/commands/ap-helpers.js:9` and `src/model/moon.js`. AP precedes season work. No RNG.
3. Set `seasonTicks = 60 * duration` for a positive integer duration, defaulting to 8 seconds. Derive `simTime = simStepIndex / 60`, `seasonClockSec = (simStepIndex % seasonTicks) / 60`, and `seasonTimeRemaining = (seasonTicks - simStepIndex % seasonTicks) / 60`. At an advancing second with zero remainder and a nonempty season list, derive season and year from the elapsed season count. No RNG.
4. On a new second only, `runLiveSecondStages` invokes `stepDetailedSettlementsSecond` if `variantFlags.settlementPrototypeEnabled === true`. The clock passes the season-boundary flag to that dispatch. See `src/model/live-second-stage-scheduler.js` and `src/model/commands/simulation-commands.js`.
5. Replay and projection apply journal actions at their second after the official ticks, in supplied order. Projection then canonicalizes and publishes its summary and optional anchor; no extra gameplay tick occurs. `src/model/replay-second-runner.js:64`, `src/model/projection-chunk.js:175`. A second which makes the run terminal succeeds if time advanced; further attempts fail.

### Shared Practice execution and event queue

- `runPracticeActivation` (`src/model/detailed-settlements/practices.js:152`): upkeep first (full-map only; exclude postRouting/afterMeals), then active sites and slot order. Schedule checks type/also, explicit stage when supplied, season keys and moon cadence. Re-evaluate staffing and conditions immediately before each plan. Try local recipes first across all sites; failed slots register one shared retry. Stock planner writes only on commit, trades with eligible road-connected and adjacent markets, and shares eligible neighboring player hosts. Population conversion is planned atomically alongside Stock. See `stock.js`, `workers.js`, `political-recipes.js` in the same directory.
- `resolveRecipe` (`practices.js:235`): evaluate all effect amounts against pre-commit context, apply Stock and population plans, emit consumption, apply external action, reset Charge for Discharge, then execute effects in array order. Effects can write `D.practiceSlots[].stock/charge`, cohort/Force/support/seasonal bonuses, `C.research/candidateDevelopment/phaseModifiers/chaos/history`; direct Spawn can recurse into political/spatial transitions. Trace activation and emit completion. No RNG. `emitPracticeEvent` (`practice-events.js:8`) appends ID, root ID, parent ID and second to JSON pending queue; game-relevant caller data and faction context are retained. Trace is capped to 100 worldwide and 100 per affected site.
- `drainPracticeEvents` (`practices.js:297`): return if a root is still executing. FIFO across pending events/roots, record trace, grant Charge in site/slot order, then try local Discharges in site/slot order. A full eligible slot can retry on a local event without matching its gain trigger. Shared scheduled retries come after existing events, then deferred Discharges in first-insertion order, retaining the first eligible parent. Drain every shared recipe's children before the next shared attempt. Once per instance (or site/slot fallback) per root; refill survives. Stop a root at the per-event or per-resolution cap, deleting its pending/deferred work. Scratch maps/sets die at end of synchronous drain; `activeRoot/activeEvent` are cleared in `finally`. No RNG. These scratch structures are local to execution.

### Timed Life Map resolution

`completeNodeResolution` (`src/model/vassal-life-map/lifecycle/node-confirm.js:464`) applies any completion-time class action, ensures Commission offers, credits ordinary node Prestige/EXP (zero for Delve/encounter), computes earned level choices, then makes one natural-mortality draw on `rng.vassalSeed`. Updates mortality, flags, completion IDs and pending transaction. A Mandate can intercept death; actual death/retirement calls `finishVassal` (line 305), which records outcomes, resolves inheritance, clears the active ID and either ends the run or rolls new candidates. Inheritance break checks/candidate ordinary rolls use `rng.vassalSeed`; portraits use `rng.vassalPortraitSeed`. Surviving encounter returns to its options; surviving Delve refreshes offers (conditional `rng.vassalSeed`); surviving ordinary node exposes outgoing nodes and queues shuffled stat choices via `rng.vassalDevelopmentSeed`. Commission target selection can consume `rng.vassalSeed` both before and in completion. Class actions can write site population, research, treasury and event journals. Topology stream `rng.vassalLifeMapSeed` is consumed by Vassal selection, an input action (`lifecycle/candidates.js:192,220`), not by timed completion or new candidate generation. `rng.baseSeed` is read-only seed provenance/derivation, not an advancing stream. Immediate risk, transaction staging, relic offers and acquisition appear on the action side of this boundary. A zero-time confirm can call the same completion routine synchronously.

## Native stepping and work per boundary

**Proposed native contract.** Execute the coarsest semantic timeline: a queue of integer-second deadlines plus a per-second read interface. The engine publishes the authoritative state after all work due at second `t`, including journal actions for `t`. Keep independent deadlines for seasons, lunar phases, timed Vassal resolutions, and player actions. Bucket ties in the order above. Native season and year changes use exact configured integer seconds. For fractional durations accepted by direct configured initialization, preserve the input value and use the clock’s eight-second fallback. A paused/terminal run has no future ticks. Retain periodic typed snapshots plus per-second deterministic deltas, immutable sharing, or bounded reconstruction. Any second must resolve to the state and summary through this interface. For a quiet interval, project clock/AP fields from the clock and share the unchanged data/summary columns. Housing reservations, event attribution, Unrest income, and scheduled deadlines must still be reconstructible on every indexed second. The default one-second lunar phase schedule means the simulation currently has substantive work at nearly every second. The main collapse available on that workload is the 59 subsecond iterations, followed by skipping redundant work inside each second.

### Summary dependencies and data access

`src/model/projection-summary.js:33` always emits second/year, terminal status/time, selected Vassal ID, its pending resolution deadline, and latest selected Vassal end second. It emits civilization and per-site graph columns. Main data dependencies are:

- `world.sites` and `world.regions` drive per-site rows and territory summaries. Reads include ownership, active/neutral status, population allegiance/cohort bins, garrison supply/support target, political Force, housing/capacity, roads and neighboring military support, and Unrest remaining time. `C.prestige` supplies Treasury/Prestige. The full-map row includes allegiance, supplied/required Force and Unrest, and also the broader territory records. See `src/model/detailed-settlements/territory.js:44` and `src/model/detailed-settlements/territory.js:100`.
- Local and global graph series read people, free workers, Faith, happiness, edible Stock, housing, Chaos, raw pressure, Resistance and Monster count. They read class age totals, happiness and faith state, practice/workforce and Structure assignments/definitions, `C.chaos` ledgers and phase modifiers. Global political/economic totals use player-controlled sites where the selectors require player scope. `src/model/graph-metrics.js:81`, `src/model/graph-metrics.js:288`, `src/model/graph-metrics/read-context.js:9` cache population, workers, territory and civilization views within one summary.
- Trace journals, full Life Map graphs and immutable gamepiece config do not need to be copied into each summary. State restoration still needs the full transaction, map, journal and RNG information for the chosen second. Store indexes and summary aggregates alongside state, update them at mutations, and compare them to a full rebuild in tests.
