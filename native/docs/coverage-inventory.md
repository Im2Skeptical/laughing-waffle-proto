# N06 native player coverage inventory

Baseline `a6e5786e`, game build 1.1.83, GameState v53. The browser reference is the ordinary full-map game reached through the active Pixi root. The native reference is the connected `waffle_native_game` target through N04m. Evidence is the active view and command wiring, the native read models and event handlers, the [N04 work plan](../WORKPLAN.md#n04---connected-playable-slice-pending-n02-and-n03), [connected slice](connected-slice.md), and [interaction design](interaction-system.md). The work plan's later N04 entries supersede early slice limitations. Status describes player access in the connected app independently of core replay support. This is a source audit with a headless browser-model replay for the population case. Desktop captures and physical-device tests were outside this audit.

**Done** means the player can complete the workflow or obtain the stated reading. **Partial** means a path or reading exists with a substantive gap. **Missing** means the connected app has no player access to it. Size estimates the remaining work. **S** is a focused change, **M** is a bounded feature slice, and **L** spans multiple flows or requires interaction and platform work. A dash marks completed coverage or a feature excluded from player scope.

## Southern Forest population finding

An ordinary browser seed 42 with an empty action journal reaches second 1584 with Southern Forest (`R16`) at `controller: frontier`, Monster Strength 3 and its site at `simulationMode: ruin`. Its retained Villager ledger contains 6 children and 18 adults, with zero Elders and zero Strangers. The detailed-settlement view-model query returns `null`. The browser map suppresses the town crest and shows the Monster badge. Its selected-region panel shows the Monster and Strength with lair art, omitting both a population number and an active settlement economy. Double-tap detailed-site entry also requires a valid detailed view model. [Browser site query](../../src/model/detailed-settlements/queries.js), [browser map wiring](../../src/views/world-map-pixi.js), [selected-region panel](../../src/views/chronicle-world-panels.js).

The native **0** is the default `SiteSummary.population` for a region that the summary never visits. `summarize` only populates rows for sites indexed with `simulationMode == detailed`. The native **24** comes from the retained site's `populationByClass` census. The initial Monster site and sites overrun later enter ruin mode without clearing the underlying cohorts. Reconquest can use the retained count when restoring a site. The zero therefore means the site is outside the active settlement metric, and the 24 is dormant site data. [Native summary](../src/timegraph/summary.cpp), [site index](../src/sim/state/runtime_state.cpp), [native census](../src/ui/settlement_model.cpp), [browser initial ruin](../../src/model/full-map-world.js), [browser loss and reconquest](../../src/model/detailed-settlements/external-world.js).

Recommend presenting **Monster-held ruin · Strength 3** with the available Monster threat information, and suppressing the active residents total, cohort rows, meal/housing ratios and active board tabs while the site is a ruin. Base the UI on site mode as well as occupancy so a cleared but unrestored ruin also receives an appropriate landing state. In native, `snapshot` currently uses `!site.neutral` for `region.detailed`, and the inspector looks up the retained site by region. Use the explicit site mode for inspection eligibility. Keep the active graph metric and saved cohorts as they are, and show the actual census again at a viewed second where the settlement is detailed. [Native snapshot](../src/app/connected_session.cpp), [native Overview](../src/app/connected_settlement_view.cpp).

Reproduction from the repository root in PowerShell. This uses the browser's official replay tick path and stable region ID without launching either app.

```powershell
@'
import { createNewGameState } from './src/model/new-game.js';
import { advanceReplayStateToSecond } from './src/model/replay-second-runner.js';
import { getDetailedSettlementViewModel } from './src/model/detailed-settlements/view-model.js';
const state = createNewGameState(42);
const replay = advanceReplayStateToSecond(state, 1584);
if (!replay.ok) throw new Error(JSON.stringify(replay));
const region = state.world.regions.find(region => region.id === 'R16');
const site = state.world.sites.find(site => site.regionId === region.id);
const { children, adults, eldersByAge } = site.detailedState.populationByClass.villager;
console.log(state.tSec, region.controller, region.monster.defense, site.simulationMode,
  children, adults, eldersByAge.reduce((sum, row) => sum + row.count, 0),
  getDetailedSettlementViewModel(state, region.id));
'@ | node --input-type=module
```

Expected output `1584 frontier 3 ruin 6 18 0 null`.
