## Findings requiring repair

Here, **draft** means `docs/performance/perf-hillclimb-20261104/drafts/feedback-runtime-v1.mjs.txt`; **runtime** means `scripts/perf-hillclimb/browser-runtime.mjs`. Priorities concern measurement validity/retention, not hypothetical security or cosmetics. Reproductions below are causal walkthroughs, **not executed results**.

1. **P1 — Original queue delay is replaced with observer arrival delay.** Draft **199, 208–210**; runtime **123–135**. With `captureInputTiming:true`, HC records its handler start and queue delay, then executes the timing-snapshot read before this observer runs. For an event stamped 100, HC arrival 105 and a 20 ms read, HC queue delay is 5 ms while the observer reports about 25 ms as `inputQueueMs`. The original input timestamp itself is preserved. **Smallest repair:** validate/copy `operation.started`, `handlerStarted` and `inputQueueMs`; retain observer arrival and HC-to-observer delay under separate names. **Control:** virtual known-cost capture read plus queued input; later an actual trusted queued-input case must preserve exact HC start/queue fields, with capture-read/observer costs separate.

2. **P1 — Arm-time baseline drift can manufacture action feedback.** Draft **154–155, 195–215, 251–255**. Arm at visible pose A; before input, an existing animation/reveal changes the same valid source to B; then deliver an input that produces no visual change, such as a clamped pan. The only baseline is A, so B can validate as feedback to that input. Correct source lineage alone does not distinguish this from an action-caused response. **Smallest repair:** enforce/prove arm-to-input quiescence or compare a guaranteed pre-app-handler input-time cue against the arm baseline and fail on drift; never silently rebaseline after action handlers. Account for the added read. **Control:** virtual same-source pre-input change followed by no-op input must not produce feedback; actual clamped/no-motion and autonomous-update cases must demonstrate the chosen pre-handler ordering/quiescence contract.

3. **P1 — Deadline/collection bypass operation status and lose its failure cause.** Draft **121–142, 226–240**; runtime **189–193**. Arm both observers, call `__HC__.cancel('functional failure')` before input, then collect feedback: `finish()` marks it censored with `error:null`, without consulting the retained original operation. With no collection/frame, the feedback deadline similarly reports no input/response even if HC was cancelled or replaced. After input, `stillCurrent()` reduces host error/timeout to generic cancellation. **Smallest repair:** reconcile runtime/operation identity and copy host error/timeout/cancellation status on every exit, including deadline and finish, preserving host outcome separately from feedback availability. Explicitly pair host cancellation with feedback cancellation before input so cleanup is immediate without an idle loop. **Control:** virtual cancel/error/runtime-replacement before input and with frames suppressed, plus timeout-versus-cancel ordering; verify retained cause, listener/timer/frame cleanup, one collected record and successful next arm. Actual integration must prove paired cleanup on job failure.

4. **P2 — `queueMicrotask` is not a guaranteed post-handler observation.** Draft **214–216, 168–177**. For native event dispatch, a microtask checkpoint can run after the document capture callback and before later target/bubble handlers. The labelled `after-input-task` read may therefore see baseline even when the target synchronously produces feedback. First rAF then only creates a candidate; two more rAF callbacks are required. Relative to the intended post-handler read, this adds a frame and can censor immediate feedback if collection follows an earlier terminal marker. **Smallest repair:** use a declared, cancellable post-dispatch observation mechanism with proven ordering, or explicitly redesign/label the frame-only detection contract and its extra observation delay. **Control:** virtual callback-order variants and an actual trusted input recording capture → microtask → target → frame order; test synchronous feedback with immediate and delayed completion. A JS-dispatched event alone cannot establish native ordering.

5. **P2 — The retained late marker is omitted from completion-order classification.** Draft **179–187, 231–233**. Let the final cue read straddle the deadline while the HC completion marker is earlier. The late branch retains `lateValidatedFeedbackMs` but clears `firstFeedbackAtMs`; collection consequently sets `markerAfterCompletion:null` despite an observed marker known to follow completion. **Smallest repair:** retain an absolute late-validation timestamp and classify marker ordering using the accepted or late marker, preserving its censored status. **Control:** virtual final-read deadline overrun with completion both before and after that marker; later actual callback/collection ordering must retain both timestamps and the correct flag without making late feedback comparison-eligible.

6. **P2 — Session history is unbounded and reinstall silently discards it.** Draft **5–10, 243–245, 264–273**. Per-operation sample caps/flags are explicit, but every finish appends a full record forever, and `history()` serializes the entire session. Reinstall is allowed when inactive and replaces the only history handle, losing prior failures/late records. **Smallest repair:** define a bounded, counted drain/export lifecycle outside measurement clocks; prevent silent replacement until records are exported or an explicit recorded reset occurs. Preserve total/truncated/exported counts rather than silently dropping observations. **Control:** virtual many-operation/overflow, failed-arm/cancel and reinstall cases must prove bounded retention and exact accounting, then verify export overhead outside actual timed populations.
