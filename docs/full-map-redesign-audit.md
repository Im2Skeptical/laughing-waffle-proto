# Full-map redesign: proposal audit and implementation contract

Historical proposal audit. Its isolation and delivery restrictions describe
the original authorization, superseded by Cam's subsequent request for
[first-class main integration](full-map-main-integration.md). The mechanical
contract below remains the implementation reference unless revised there.

Audit date: 2026-10-31. Baseline: `c5289550fba6bedc8b6c2ae16dd4421bafbb1535`, version `1.1.31`, branch `proto/full-map-bronze-card-review`. Initial working tree was clean. This report is the only authored change; investigation was read-only. No gameplay, UI, registry, schema, branch, PR or publication changes were made.

**Verdict: implementation may proceed in this experimental fork, with the corrections below.** The loop is sound; the current runtime is not already a compatible implementation. Several failures would be structural, not tuning problems. Do not promote the catalogue's face adapter as executable content. No remaining question requires Cam to answer before implementation; every unresolved coefficient below has a proposed default. Parent should explicitly retain or revise the marked defaults when issuing the implementation brief.

## Authority and scope

Cam's latest task agreement overrides older review assumptions and current-behavior documentation. Implement the real normal-scale region map (default 20), actual gameplay and renderer, as the fork's default Load/New Game path. Preserve the old game separately first. No miniature, detached demonstration, publishing or integration is authorized.

The agreed loop is economy → vassal intervention → conversion/conquest → inherited mixed board → stabilisation/renewal → territorial Prestige → preparation against monsters. One passive inherited enemy capital, one main class initially; feuding oligarchs and a secondary class splash are later experiments. Vassals remain Warlords/Philosophers; population specialties are Warriors/Scholars, with Priest/Merchant cohorts only where used. Protovassal redesign is unnecessary.

Agreed invariants for the implementation:

- All regions inhabited initially; player controls 1–2. Five Practice slots each; Structure capacity separate. Inherited useful, weak and harmful pieces; denser enemy institutions near its capital. The reviewed 20 player, 30 neutral, 80 enemy and eight capital candidates are sources, not 138 working simulation definitions.
- Influence is discrete population allegiance, all living ages included. Specialty and allegiance are independent. Regional controller and population support are distinct; supplied loyal military can occupy opposition. Actual holder change transfers access to physically hosted Stock immediately.
- Structures and Resource Practices have no allegiance. Influence Practices carry allegiance per installed instance, retained on capture. Class, cult and art identity never determine hostility. Influence cards receive distinct frames, conversion fittings and an allegiance badge; Resource cards retain Stock fittings.
- Zero workers means base effect, factor 1. Workers never gate execution. Neutral workers staff Resource Practices; loyal workers prefer their own Influence Practices, then Resources, never opposing Influence. Preserve specialist eligibility/capacities, automatic assignment and deterministic board order. Explicit ingredients, victims, reserves and eligible targets remain real conditions.
- Automatic local recipes can use local Stock regardless of Practice allegiance. Remote Resource inputs follow the controller's allies; remote Influence inputs follow the installed allegiance's allies. Local first, real connections/reach, atomic complete recipes; no global warehouse or partial reservations.
- Territorial Prestige is recurring and global, reduced by unrest, with a starting reserve. Outside-territory interventions depend on vassal reach, not ownership. Keep Prestige shortfall → Monster Pressure substitution. Enemy Influence replacement remains allowed, with installation cost plus extra Prestige and explicit Pressure taxes. Add an allegiance-changing intervention that preserves the institution. Stage/undo must remain reversible.
- Birth allegiance is proportional to local distribution; migration preserves it; deaths remove actual affected cohorts. Sacrifice remains death after capture. No shutdown/staffing toggle, compulsory recruitment bootstrap or abstract substitute for victims.
- Preserve deterministic RNG streams, JSON state, authoritative `tSec`/rebuild, model/view layering and DSL-first behavior. Clean save-schema cuts are permitted.

Pillars used below: **P1** interacting engines; **P2** constrained/random opportunities; **P3** visible civilisation transformation; **P4** playable projected consequences; **P5** customisable legacy. Inheritance supports P5's theme; this scope does not require a new cross-run legacy system.

## Severity-ranked findings and minimal resolutions

### Critical 1 — Separate allegiance cannot be added as a second population total

Evidence: `detailed-settlements/cohorts.js` stores Scholar/Warrior subsets inside Villager/Stranger age cohorts. `phases/birth.js` reproduces each specialty part; `phases/migration.js:addCompositionToStrangers` rewrites arrival status; its external movement path removes people without adding them to a foreign site's actual population. `external-world.js:conquerSettlement` erases age/specialty composition and replaces survivors with adult Strangers. These operations cannot conserve the proposed identities unchanged.

**Default:** use one authoritative joint cohort representation: residency/status × allegiance × specialty × age bucket, with integer counts. Keep Villager/Stranger as independent local residency status initially (including existing effectiveness/happiness rules); they must never mean player/enemy, loyal/disloyal, or ordinary/specialist. Arrivals may become Strangers while preserving allegiance, specialty and age. Derive aggregate summaries; do not independently mutate parallel allegiance and population totals. Introduce common select/transfer/train/kill operations used by every demographic and card path.

Conversion moves exactly `min(output, eligible opposing count)` people between allegiance bins, preserving age, specialty and residency. Training changes specialty only; combined train-and-convert selects once and changes both attributes of the same people. Allocate generic conversion proportionally across eligible opposing bins using largest remainders, stable faction/status/specialty/age order for ties. No RNG needed. For births, retain existing birth-count calculation initially, but assign newborn allegiance from the pre-birth local all-age distribution by largest remainders. Distribute within existing newborn specialty totals so specialty inheritance is not inadvertently redesigned. No named individuals. A Priest secondary newborn roll is deferred.

Capture changes controller, not cohorts. If a directed battle kills people, select and remove real cohorts proportionally and journal actual deaths; never reconstruct survivors as adults or create a minimum survivor. Foreign inhabited destinations use actual arrival/housing/meal handling, not the old external-emigration sink. Revalidate pending migration compositions after intervening conversion/training/death so stale reserved populations cannot be removed twice. **P3/P4;** a joint ledger adds implementation work but avoids fake influence and invisible demographic losses.

### Critical 2 — Existing supply authority and military authority leak across the new boundaries

Evidence: `stock.js:stockProviderSlots` only opens remote supply for a player-controlled destination and only offers player sources, then priced neutral inventories. It has no consumer-allegiance argument. `campaign.js:campaignForces` totals Warriors and Arms across every player site; `external-world.js:getMartialForce` uses global support/Retinue/Prowess, and `getCivilizationSupportSources` sums shared support again at receiving sites. Monster defence is player-only. Reusing these formulas would let hostile population defend the occupier and the same army hold disconnected regions repeatedly.

**Default:** make supply context explicit: consumer region, purpose, beneficiary faction, local-only/shared stage. Resource/meal/construction use the current holder; Influence uses its instance allegiance. Every remote host must be polygon-adjacent **and** directly road-connected, with controller equal to the beneficiary faction. Local Stock ignores allegiance for automatic recipes. No transitive supply, neutral-market fallback or all-neutral global alliance. Unheld regions use local automatic supply only. Plans remain pure; `Require` tests activation-start Stock and does not debit it; explicit `Consume` can spend the same required host under current semantics. Never apply a plan after controller/topology/instance changes without revalidation.

Separate automatic local recipe authority from discretionary vassal spending. A visiting vassal can install/retag in foreign territory but cannot spend that region's Currency/Edible as the player's wallet. Resource-paying interventions draw from a declared player-controlled local/eligible neighbouring source or fail for missing materials. Prestige fallback replaces Prestige, not Stock costs. Food feeds everyone locally regardless of allegiance, using local meals for every region before any neighbour meal draw; only the holder's allied neighbours share leftovers. Display the beneficiary/network and precise missing ingredient.

Use local supplied **adult loyal** Warriors for occupation and defence, with deterministic allocations for any explicitly enabled adjacent support. No global Retinue or vassal stat contributes to permanent holding. A source serving another region cannot simultaneously supply its own holding contribution. Armed campaign participants must come from declared reachable sources; a garrison left behind must be removed from those available participants. **P1/P2/P4;** physical supply supports meaningful engines and prevents free conquest by aggregate numbers.

### Critical 3 — Filling the map can remove monsters entirely and disable foreign automation

Evidence: `new-game.js` seeds four market towns, then `seedOpeningMonster`; that function requires a frontier region with no site. `pulseMonsterPressure` also needs an empty site to spawn if no monster exists; with a full inhabited map and no initial monster it has nothing to strengthen. Scheduled activations whitelist `player`/`external-a`; Charge gain considers those holders but `tryDischarge` permits only `player`. Birth/death skip `site.neutral`. These are old-model gates, not rules of the proposed world.

**Default:** all inhabited non-ruin regions simulate symmetrically, independent of controller; remove neutral-market exemptions from the new scenario. Explicitly seed a Defense-2 monster threat/nest at a distant inhabited nonplayer region. Monster presence is a threat field distinct from holder/population: seeding alone does not empty the region or grant its Stock. A pressure pulse can attack its host first if not overrun, then spread to adjacent targets using the existing rotating order; assaults use the same faction-aware defence rules for player, remnant and unheld locals. Successful overrun makes a ruin, preserving dormant boards/cohorts under explicit ruin rules. Guarantee a seed target even when every region has a site. No monster immunity for the remnant.

Retain pressure threshold 100 and Starter_02 primordial tuning initially; explicitly test it on the new map. Regional automatic death/Research/Chaos effects must not silently become player-wide effects. Keep player Chaos Resistance scoped to player-held residents, and attribute demographic Chaos income by holder at the loss event for the first pass; otherwise making 18 foreign settlements mortal increases player losses without matching resistance. Explicit action Pressure still affects the shared monster tracker immediately, whichever faction caused it. Record foreign demographic losses in regional history. **P3/P4;** monsters stay the larger threat without an active enemy planner.

### High 5 — Zero-worker operation already exists; affiliation and conversion scaling do not

Evidence: `practices.js:practiceEffectAmount` already computes Scheduled Stock using `1 + effectiveWorkers * workerBonus`; zero workers is base output. Charge uses that multiplier on **gain**, not Discharge. `conditionsMet` still has `scholarRequired` as a staffing gate. `workers.js` assigns Scholars first then ordinary tokens without allegiance; ordinary tokens include Warriors, while Scholar adults/elders are individually socketed. Candidate “requires N loyal Scholars/Warriors” clauses can accidentally reintroduce the rejected gate.

**Default:** preserve `W = 1 + effectiveWorkers * workerBonus`, default bonus 1. Scheduled Stock = existing base/flat bonuses × additive Output pool × W, floor, then existing post-yield bonuses/capacity. Scheduled conversion = floor(authored base × W) + explicit flat conversion bonuses, capped to eligible targets. Output/biome/Capacity pools never scale conversion unless a specifically named future conversion modifier says so. Charge conversion/Stock keep fixed Discharge amounts; W accelerates Charge gain only. Training-and-conversion shares one scaled target count; do not also apply the existing Scholar training doubling. Inputs, victims, reserves, Research, Force and unrelated effects never get multiplied through a generic worker path.

Remove worker-presence activation gates, including migrated `scholarRequired`. Preserve true authored population reserves where they are actual nonconsumed population conditions, but remove candidate loyal-specialist presence clauses that merely stand in for staffing (e.g. Open Lessons). In the manifest distinguish `populationRequire` from labour. Oath Supper still needs eligible opposing Warriors; it does not need two loyal workers to start. No compulsory recruit cohort.

Allocate each faction's eligible Scholar sockets and ordinary tokens to matching Influence first, then let all remaining faction/neutral workers fill Resource slots, preserving specialist socket precedence and board order within each priority. Count no person twice; no leftovers from separate allegiance/status bins may be rounded into extra workers. Recompute after population mutations before the next activation/retry. Military duty can coexist with economic labour as a simplifying default, but each Warrior contributes to only one military assignment. **P1/P2/P3;** ×1 base makes remote institutions viable, while worker acceleration rewards stabilisation. Test accelerated hostile conversion too, not just player output.

### High 6 — Victim, target, Stock and capacity payment must be one transaction

Evidence: `recipePlan` plans Stock alone; scheduled producers can pay while full, Charge only checks whether a host is already full. There is no population-cost operation. Capital rules require a complete **base** yield to fit, one real victim, reserves and no partial payment. `effectBonus` is currently broad enough to affect unrelated effects if reused carelessly.

**Default:** extend the generalized recipe plan with typed population selections/reserves, conversion targets, output destinations and base-yield headroom. Validate everything on the activation-start snapshot, then commit once; failed Stock/reserve/victim/target/capacity checks mutate nothing and emit no successful activation. Population victims/reserves may not alias illegally. Require a full base Stock yield to fit for rites; amplified excess can be discarded at capacity, as the review specifies. Resource rites consume exactly one victim, once at authored cadence, even at ×10 output. Select victims proportionally within eligible local cohorts, not preferentially from enemies. Influence sacrifice retains the Practice's allegiance filter. Removing the Resource rite's old loyalty filter is an explicit proposed content revision, not a hidden faction field.

Death updates cohort totals, specialties, workers, control inputs, histories, Chaos attribution and one death event exactly once. Controller receives new Research; remnant Research belongs in its ledger without autonomous spending; unheld production remains regional history and does not retroactively award player Research on capture. Stock stays hosted. Structure rite bonuses bind to the successful transaction/event and apply once at their stated cadence; never re-run the sacrifice. No manual mothball. Failed input/capacity/reserve conditions are legitimate automatic inactivity. **P1/P3/P4;** keeping dangerous institutions becomes an inspectable tradeoff rather than a free reward or unexplained death loop.

### High 7 — Control needs hysteresis, proportional holding and bounded unrest

No live control-conversion/unrest model exists. A majority check after each converted person would cause flicker; counting global Force would make garrisons free; resetting unrest on capture would reward cycling ownership.

**Initial defaults, all tunable:** evaluate control once after each Death phase's demographic/Practice reaction batch, in authored region order, computing all decisions from one pre-transfer snapshot. Let N be all living residents, L the incumbent's loyal residents, D=N−L. Peaceful claim requires a named faction's share ≥60% at two consecutive control checks. Incumbent support retention is ≥45%. Neutral/unaffiliated residents do not form a conquering faction.

For occupation, `armed = min(local loyal adult Warriors, local Arms units)`; `F = armed / 5 + eligible supplied Force bonuses`, `required = ceil(D / 25)`. Require at least one armed loyal Warrior when D>0, so an empty citadel cannot occupy people by itself. Arms are retained equipment; allocated units cannot equip two military contributions. Each Food phase, pay extra garrison upkeep `ceil(armed / 10)` Edible atomically, after civilian meals; failure sets supplied Force to zero until a later successful upkeep. Benefits with their own upkeep must also be paid. Ordinary defence can protect unheld residents with local Warriors; occupation always needs a named faction. At D=25 versus D=250, required Force is 1 versus 10, not the same flat switch.

Supported incumbent: target unrest 0. Adequately supplied occupation: target `25 + 50*(D/max(1,N))`. Neither condition: target 100. Move unrest toward target by at most +15 or −10 per control check, clamp 0–100. A supplied occupying incumbent blocks a peaceful rival claim; mark the rival's support in inspection. Without that garrison a two-check ≥60% claimant succeeds. Otherwise an unsupported/unsupplied holder loses to unheld after unrest ≥75 at two consecutive checks. Candidate/check counters reset when conditions break. A depleted region N=0 earns no Prestige, cannot be peacefully claimed and becomes unheld. Actual resident garrison people count in N; a marker is not population.

Capture does not clear unrest: peaceful change reduces it by 20, floor 0; military capture sets at least 50. Reclassify displayed state as supported/occupied/contested from current conditions; maintain one actual holder while contested. Stock authority changes exactly at the holder transition, no relocation or allegiance retag. Military victory changes holder immediately; subsequent checks decide whether it can be retained. The directed action may bring real Warriors: reserve a detachment from declared reachable player sources, remove it from those source counts, and move surviving cohorts into the target on victory. Automatically leave the smallest available detachment satisfying the displayed holding requirement; if insufficient, show contested control rather than invent loyal population. First-pass battle victory need not kill civilians: default zero civilian/Stock attrition, preserving the inherited board; defeat retains the existing vassal-risk outcome. Any later authored troop/civilian losses must use the same cohort-removal operation. Expedition Food is paid before departure, and Arms moved for the garrison must debit actual hosts and fit destination Resource capacity, or that equipment cannot be supplied. No carried/global inventory is implied. Forecast must show supplied Force, required Force, unrest direction and expected transition date. **P2/P3/P4;** hysteresis adds delay but makes control comprehensible. Test famine and sacrifice changing both numerator and denominator, not only conversion.

### High 8 — Personal Prestige, travel gates and draft identity need clean changes

Evidence: Prestige is currently `vassal.prestige`; ordinary income is per completed node (`selectors.js:getVassalPrestigeIncome`). Retinue, legacy, commissions, presentation, costs and validation read that personal field. `world-choices.js` offers movement only to connected player detailed sites; settlement-founding requires empty frontier. Shops operate on vassal location and key draft identities/replacement/undo by `practiceId`; upgrades reconstruct slots without any future allegiance. Remote footholds and political retagging would be fragile on these assumptions.

**Defaults:** one civilization Prestige treasury, starting 20, shared across successive vassals. Territory earns 1 Prestige per occupied inhabited region per simulation year × `(1−unrest/100)`. Accrue by elapsed simulation time using the holder/unrest applicable during that interval; pay/round deterministically with a serialized fractional remainder, never by rendering or by a snapshot of holdings at payday. Keep existing node rewards and commissions initially but route them through one income ledger; retirement does not refill the treasury. Retinue still uses the existing held-Prestige/10 rule for the active Warlord's personal expedition only, not every garrison. Ensure passive income counts once for gross-income commissions. Watch territorial growth making purchases trivial; tune rate before adding new caps.

Keep the Life Map, shops and costs; allow movement to inhabited foreign regions along existing road paths irrespective of holder. Add a vassal expedition destination through Crossroads using physical adjacency distance when there is no road path: default two years per map edge, no new road or automatic Stock connection. It is disconnected from territory/supply, not a free teleport. At the destination ordinary node constraints govern intervention; no territory prerequisite. Offer allegiance reform at Practice Reform: 10 Prestige and two years to adopt one installed Influence institution, preserving identity, art, Charge and other private state. It converts no population instantly. Guarantee access to this action without requiring a fortunate card draw. Directed campaign remains a Warlord node; non-Warlord civilisation still has automated Warrior defence/holding and institutional expansion.

Replace draft/action references with stable installed instance IDs and explicit target region. Preserve these IDs/allegiance through move/reorder/upgrade/save; new installation gets a new ID and player's allegiance if Influence. At most one copy of a definition per region can remain an initial content restriction, but is not a substitute for instance-safe APIs. Retag cannot change art/cult/pool. No direct free reorder/demolition of foreign boards outside a vassal transaction. **P1/P2/P5;** shared income strengthens the territorial loop and legacy, but its Retinue feedback must not grant free worldwide defence.

### High 9 — Hostile replacement taxes can be bypassed through ordinary draft displacement

Evidence: shop receipts currently reserve Prestige and defer Pressure until confirm. `getShopOfferPrice` substitutes **the entire insufficient card payment** with 10 Pressure and spends zero Prestige; it is not a proportional exchange rate. Confirm installs the board and flushes events before adding Pressure. Campaign and other action costs still have hard insufficient-Prestige gates.

**Defaults:** enemy Influence replacement costs normal new installation + 5 additional Prestige + 10 explicit Monster Pressure. Determine hostility from the confirmed installed instance's allegiance against the acting faction. Resource/Structure replacement has no political tax. Charge the tax for every hostile confirmed Influence instance removed by replacement, capacity displacement or vassal removal; otherwise discard/reorder becomes a free political purge. Never prohibit the replacement.

Preserve the existing all-or-nothing substitution policy per logical installation: aggregate discounted installation Prestige plus its 5-point tax, then either pay that whole Prestige amount or pay 10 substitution Pressure with zero Prestige debit. Always add the separate 10 hostility Pressure. Example: available 12, ordinary price 10, hostile tax 5 → 0 Prestige and 20 Pressure; available 15 → 15 Prestige and 10 Pressure. Do not silently change to a per-point exchange rate. Route new reform/intervention Prestige costs through the same policy; explicitly reconcile existing Campaign hard gates if it becomes part of this expansion interface.

Stage from the confirmed board, reserve all costs, recompute after every edit, and commit once after validation. A staged retag cannot wash away the confirmed hostile-displacement tax; retaining a reformed institution is untaxed, replacing it in a later separately paid visit is legal. Add one transaction ID and instance-specific removal receipts. Apply the entire chosen intervention, material/Prestige debits and successful-event journal atomically, then resolve its total explicit/substitution Pressure before time advances. If it ends the run, do not continue stale visit processing. Undo/discard before confirm changes neither treasury nor Pressure/RNG. **P2/P4;** taxes preserve choice and make the rejected “cannot replace enemy cards” restriction unnecessary.

### High 10 — Cadence, event attribution and projection must agree on capture

Evidence: `phases.js` runs seasonal work first, phase work next, then vassal stepping; Food's existing `postRouting` activation actually occurs before meals. `matchesEvent` filters class/pool but no faction; `anotherPractice` compares definition IDs. Pending recipes and shared retries re-read Stock/staffing; introducing conversion makes stale assignments within the initial scheduled pass significant. Events such as defence must carry a faction, not assume player ownership.

**Default ordering:** retain the official tick/action replay boundary and 60 ticks per second. Within settlement phase work retain separate seasonal/phase trigger batches, local-only scheduled pass → local FIFO reactions → shared retries. Re-read workers/targets before every recipe after an earlier population change. Snapshot beneficiary/actor faction and instance ID on events; capture cannot rewrite historical event allegiance. “Another Practice” uses instance identity. Keep one Discharge per instance per root and bounded chains. Do not reset Charge merely because control changes or replay reads an instance.

Make Food stages explicit: ordinary production/recipes → every local civilian meal → eligible neighbour meal supply → meal-resolution event/relief conversion → garrison upkeep. Frontier Relief tests a recorded shortage and actual beneficiary-attributed relief, not just an Edible Consume recipe. Its extra 3 Edible cost does not retroactively count as feeding the meal. Death: demographic losses → death Practices/reactions → control checks → spatial monster step → final phase events/reactions. Pressure generated by a recipe resolves after that recipe commits, before the next unrelated recipe; revalidate any later candidate whose site was lost. After final reactions/vassal resolution refresh summaries and loss detection; next cadence handles newly changed support rather than recursively re-running control checks.

Use an explicit territorial-loss terminal reason if player holdings reach zero; do not label peaceful political loss “monster overrun.” Keep the existing last-territory loss convention for the first pass; a surviving remote Influence piece does not silently prevent loss. A vassal legitimately visiting foreign territory must not be teleported home by the current “location is not player-owned” evacuation check; evacuate only on an actual newly invalid/lost location. **P4** is a hard requirement: forecast uses these same transactions, events and state, not an approximation or decorative influence line.

### Medium 11 — Seeded boards, content access and performance need acceptance coverage

The map already has seeded 20-region geometry and nine roads. Keep that geometry/revision and scale. Recommend enemy **Warlord** (`dictator` source pool), reusing established Warrior support and a real population-consuming Arms rite without requiring Priest population before the first test. This is a proposed default, not Cam's selected enemy class.

Pick the enemy capital maximally distant from the player start by polygon graph distance, stable authored tie order. Keep the existing two-region player road start. Capital/province/outskirts: populations 120/60/30 initially; player starts retain the existing 20 per region. Use 80% player allegiance in player starts, 80% remnant at enemy capital, 60% at its adjacent provinces, 20% remnant elsewhere; the rest unaffiliated. Start capital and adjacent provinces remnant-held, distant outskirts unheld. Seed adult Warrior cohorts sufficient for the capital's actual rites/reserves; no active strategic recruitment AI. Capital structures fit the existing 5–8-cell capacity, including a three-cell rite support if selected; never fit several three-cell capitals into five cells.

Candidate 4 enemy/1 neutral, 3/2, 1/4 gradients are selection targets, subordinate to **functional five-slot recipes**. Choose bundled boards with Food, Housing and required supply, not five independently random expensive cards. The capital can use ration conversion + population-consuming Arms + salvage + another compatible enemy institution + neutral Food, with each cycle/reserve proved. At least one adjacent player opportunity supports base conversion at zero loyal workers; at least one remote disconnected destination is viable by expedition; one inherited sink must actually activate and one retained hostile Influence must be observable after capture. Add useful dependency providers from the existing resource registry when the reviewed set has no provider (e.g. Paper/Tool/Record chains); record the source instead of inventing free Stock. No immunity or per-turn spawn cheats to make the display look viable. Guarantee starter subsistence/Housing and two complete meal/upkeep cycles of initial hosted inputs within capacity, then let production matter.

Do not let new candidate shops become all conversion with no economy, or let old neutral-market/trade/raid definitions remain purchasable dead ends. Adapt their generalized targets to real hosted Stock or explicitly exclude them from the fork's offer pool. Preserve the early Warlord/Philosopher path through existing protovassal founding. Build a per-offered-card dependency/cadence coverage list. Phone forecasting with 20 live boards is substantially more work than the existing two player plus fixed markets; profile the real scenario before reducing scope or inventing a second fast simulation. **P1/P2/P3/P4;** mature capital power comes from inherited combinations with brittle supply, not limitless resources.
