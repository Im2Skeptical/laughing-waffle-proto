# Axmol maintenance and developer experience

Verified **2026-11-13**. Scope: Axmol evidence for a greenfield illustrated 2D strategy game with substantial custom UI/timegraph and deterministic forecasting, targeting Windows and Android Pixel 6. This is research, not a benchmark.

## Current maintenance

**Axmol is actively maintained.** Latest stable is **2.11.5 LTS, published 2026-09-25**; preceding patches include 2.11.4 (2026-07-06) and 2.11.3 (2026-02-23). The production branch is `release/2.x` (C++20); default `dev` is v3 development (C++23). The homepage says “3.0.0-beta1 · Public beta”, but its [v3 page](https://axmol.dev/v3/) explicitly says the tag/download is pending, and the [README](https://github.com/axmolengine/axmol/blob/dev/README.md) says beta1 is in preparation. The [release API](https://api.github.com/repos/axmolengine/axmol/releases?per_page=100) contains no v3 release; the [beta-tag lookup](https://api.github.com/repos/axmolengine/axmol/git/matching-refs/tags/v3.0.0-beta) returned none. Treat v3 as a prerelease evaluation branch; its newer rendering backends are not v2 capabilities.

**Visible maintenance is concentrated, with multiple contributors.** For 2026-10-14 through 2026-11-13 UTC, the complete API result contained **27 `dev` commits by five linked authors**: halx99 17, aismann 5, NgVThangBz 3, sameer-manek 1, iAndyHD3 1. `release/2.x` had **four commits by three authors**: halx99, rh101 and AlexandreK38. These are commit-author counts for a defined window, not employee or maintainer headcounts. They show activity and concentration without establishing support capacity. Sources: [dev commits](https://api.github.com/repos/axmolengine/axmol/commits?sha=dev&since=2026-10-14T00%3A00%3A00Z&until=2026-11-13T23%3A59%3A59Z&per_page=100), [v2 commits](https://api.github.com/repos/axmolengine/axmol/commits?sha=release%2F2.x&since=2026-10-14T00%3A00%3A00Z&until=2026-11-13T23%3A59%3A59Z&per_page=100).

- **2026-11-10:** rh101's [#3409](https://github.com/axmolengine/axmol/pull/3409), Android manifest theme/startup compatibility, merged into `release/2.x` by halx99. Branch fixes are not automatically in the September release.

Conversely, pesbbaddo's [#3365](https://github.com/axmolengine/axmol/issues/3365), opened 2026-10-03, reports intermittent Windows v3 scene-priority pointer-event loss; tkzcfc's [#3386](https://github.com/axmolengine/axmol/issues/3386), opened 2026-10-18, requests thread-safe v2 file-path resolution. Both remained open with zero issue comments when checked. These are reporter claims/requests, not independently reproduced defects or merged fixes. Responsiveness varies; a small community is not inherently a quality problem.

The [official website](https://axmol.dev/) names Simdsoft Limited as project lead/maintainer and Scorewarrior as a long-term financial patron. Those are **official sponsorship claims**, not independent evidence of staffing, funding duration or a support SLA.

## Firsthand experience

- **Julien Jorge / j-jorge — greenfield Bim!, Android, 2024–2026.** His [2024-02-29 development account](https://julien.jorge.st/posts/en/bim-talking-about-mobile-game-dev-project-management-dependencies-etc/) describes using Axmol alongside his own ECS/network simulation, but substantial integration work to build it as a library and trim dependencies. Crucially, he **did not evaluate Axmol's UI tools**: he bypassed them following earlier Cocos2d-x experience. That legacy dissatisfaction cannot establish current Axmol UI quality. His [2025-11-25/29 roadmap comments](https://github.com/axmolengine/axmol/discussions/2650) directly criticize Axmol compilation time and ownership/reference-counting constraints. Success is tangible: [2025-11-09](https://julien.jorge.st/posts/fr/sortie-du-jeu-bim-en-version-12/) reports worldwide Play Store **open testing**, GitHub and F-Droid availability; [2026-01-28](https://julien.jorge.st/posts/fr/sortie-de-bim-en-version-14-avec-des-barrieres/) documents further releases and custom UI-testing tools. This is a distributed game, beyond an engine demo, but not evidence of commercial scale. He is also an upstream contributor and reports receiving contribution rewards; he is not a wholly unaffiliated reviewer.
- **StudioNAP — Cocos2d-x 3.17.2 migration, 2026-08-24.** Reports repeated frustration and building a UI editor to convert `.csb` files to JSON, yet concludes Axmol is adequate and elects to port. This is a migration decision, not a completed/shipped port or greenfield account. [Firsthand reply](https://www.reddit.com/r/gamedev/comments/1vww21b/comment/p5lh13j/); [JSON timestamp](https://www.reddit.com/r/gamedev/comments/1vww21b/is_migrating_from_cocos2dx_to_axmol_a_good_idea/.json).
- **grif-on — Windows setup, 2024-06-13.** Documents functioning prebuilt-engine integration and Lua debugging with Windows 10, VSCode, MSVC x64 and Axmol 2.1.3; also describes CMake configuration traps and debugger limitations. This is useful workflow evidence, not a shipped-game report or Android validation. [Discussion #1989](https://github.com/axmolengine/axmol/discussions/1989).
- **Ts-pe — fresh Windows projects, 2025-02-07–16.** Reports Lua/C++ startup failures on Windows 11 Insider. rh101 answered on the opening date; halx99 participated in diagnosis. The user eventually reported working code after a Visual Studio update, attributing the problem provisionally to environment configuration. This shows hands-on support and setup friction, not a proven current Axmol regression. [Discussion #2378](https://github.com/axmolengine/axmol/discussions/2378).

Independent, detailed greenfield production evidence remains **sparse**. These selected accounts do not support a satisfaction rate; historical setup reports do not establish today's documentation quality.

## Implication for this project

**Inference:** retain Axmol on the shortlist, with v2 LTS as the conservative baseline and v3 evaluated separately. Its maintenance is demonstrable; the prior Axmol versus purpose-built SDL3/RmlUi recommendation remains architectural and unmeasured. Before selecting, measure representative illustrated-map/UI rendering, timegraph drag/scrub latency, forecast isolation and replay hashes on Windows **and the actual Pixel 6**, including Android lifecycle interruptions. None of these sources verifies this workload's determinism or Pixel 6 performance; desktop results cannot establish either.
